# Разработка и публикация

[← На главную](../README.md)

Команды ниже выполняются из корня репозитория.

## Отдельная рабочая копия

Для разработки запускайте `./run-dev.sh`. Скрипт собирает ALOL при доступном Cargo
и запускает его прямо из проекта. Если Cargo недоступен, используется существующая
сборка с сообщением об этом. Бинарник остаётся в проекте, в меню приложений рабочая копия не добавляется.
Настройки, кэши, префиксы и журналы разработки находятся в `.dev-data/` проекта
и исключены из Git и релизного архива. По умолчанию проверка обновлений в этом
профиле ручная; рабочую сборку обновляют через Git и пересборку.

Установленная отдельно версия из GitHub использует обычные пользовательские
каталоги ALOL. Сборка внутри репозитория использует отдельный ID окна `alol-dev` и не заменяет
себя релизным бинарником через self-update. Для иконки Wayland создаётся скрытая
запись `alol-dev.desktop` с `NoDisplay=true` в пользовательской папке applications.
Она указывает на `run-dev.sh` и иконку из проекта, не копирует программу в систему
и не подменяет `alol.desktop` установленной версии. `ALOL_DESKTOP_DATA_HOME`
сохраняет путь к обычной папке desktop-метаданных до изоляции XDG-профиля.

Для Arizona UMU получает отдельный GAMEID (`umu-alolarizona`, в разработке
`umu-alolarizonadev`), чтобы не использовать общий класс `steam_app_default`.
Скрытые записи связывают эти окна и известные имена Wine-лаунчера с иконкой ALOL.
Чужие пользовательские desktop-записи не перезаписываются.

## Проверка изменений

```sh
cargo fmt --all -- --check
cargo clippy --offline --all-targets -- -D warnings
cargo test --offline
cargo build --offline --release
PYTHONDONTWRITEBYTECODE=1 python3 tests/integration.py
PYTHONDONTWRITEBYTECODE=1 python3 tests/mods_integration.py
PYTHONDONTWRITEBYTECODE=1 python3 tests/game_integration.py
PYTHONDONTWRITEBYTECODE=1 python3 tests/update_integration.py
```

Интеграционные тесты используют временные каталоги и подставные Windows-runner/API;
они проверяют работу ALOL, а не совместимость игры с Wine.
При доступной графической сессии: `target/release/alol --smoke-test`.

Контраст всплывающих списков, разделов обслуживания и размер заголовка проверяются
с реальными GTK-виджетами в светлой и тёмной темах:

```sh
GTK_THEME=Adwaita PYTHONDONTWRITEBYTECODE=1 python3 tests/gui_theme.py
GTK_THEME=Adwaita:dark PYTHONDONTWRITEBYTECODE=1 python3 tests/gui_theme.py
PYTHONDONTWRITEBYTECODE=1 python3 tests/gui_app.py
```

Тесты обновлений используют отдельную копию ALOL во временной папке, локальные
фикстуры GitHub и подставной пакетный менеджер. Настоящий установленный ALOL
и системные пакеты при проверках не обновляются.

`tests/gui_app.py` проверяет настоящее окно ALOL через временный GTK test module:
автопроверку, ручной режим, окно релиза, сохранение настроек, отмену и повтор после
ошибки, иконку и desktop identity, сохранение настроек из закреплённой панели
и переход к восстановлению. Нужны графическая сессия и GTK development headers.
Тесты запуска Wine подставляют конфликтующие переменные Hyprland/niri и проверяют,
что совместимый режим ограничивается официальным лаунчером.

Для дополнительной проверки на настоящем Wine (нужны `wine`, `winegcc` и
`wineserver`), без загрузки игры или winetricks-компонентов:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 tests/wine_language.py
```

Тест создаёт два временных префикса: локаль ALOL и запасной режим без `localedef`.
Windows-программа проверяет ACP 1251, OEM 866 и ru-RU. Префиксы и их wineserver
удаляются после проверки; личный префикс не используется. Это отдельная проверка,
она не входит в обязательную сборку пакета.

## Публикация и проверка файлов

`scripts/package-source.py` упаковывает исходники по явному списку без `.git`,
сборок, профилей и домашних каталогов. `scripts/audit-release.py` проверяет
точный состав архива и пакета, домашние пути, адреса почты, распространённые
форматы токенов и приватных ключей, а также записывает контрольные суммы.
PNG проверяются на целостность и отсутствие текстовых/EXIF-метаданных;
перед публикацией снимки также проверяются визуально.
Это автоматическая проверка распространённых утечек; перед публикацией также
просмотрите изменения и не добавляйте личные настройки в исходники.

Arch-сборка также экспортирует отдельный `alol-VERSION-linux-x86_64` для
обновления локальной установки. Скрипт `scripts/package-binary.py` проверяет
архитектуру и версию бинарника; аудит включает его в `SHA256SUMS`.

Для готового чистого Git-коммита и тега текущей версии команда
`./scripts/publish.sh` повторяет проверку, публикует репозиторий и GitHub Release.
Нужны авторизованный `gh` и доступ к GitHub. Скрипт не использует force push.
После загрузки основных файлов он запускает workflow `Fedora RPM`, ждёт сборку
и скачивает проверенный RPM. Для добавления workflow OAuth-токену GitHub CLI
может понадобиться scope `workflow`: если GitHub отклонит push по этой причине,
выполните `gh auth refresh -h github.com -s workflow` и повторите публикацию.
Сам токен в файлы проекта или GitHub Actions secrets не копируется: workflow
использует временный `GITHUB_TOKEN`, выдаваемый GitHub на время запуска.

## Снимки интерфейса

Сделать снимки в своей графической сессии:

```sh
./scripts/capture-screenshots.sh
```

Режим съёмки использует временные HOME и XDG-каталоги, не читает личный профиль
и отключает действия запуска. Экспортируется только окно ALOL через GTK/Cairo,
без рабочего стола, соседних окон и PNG-метаданных пользователя.
