# Совместимость

## Proton и Wine

Основной вариант ALOL — GE-Proton через UMU. UMU обеспечивает запуск Proton
в Steam Linux Runtime вне Steam и загружает необходимые компоненты.
ALOL использует `umu-run`, а не запускает внутренний `files/bin/wine`
из сборки Proton напрямую.

Для разработки профиля Arizona доступен [экспериментальный ALOL-Proton](proton.md).
Это отдельный пакет GE с нашим слоем запуска; собственных патчей Wine/DXVK и
измеренного преимущества по FPS в первой версии нет.

- [GE-Proton](https://github.com/GloriousEggroll/proton-ge-custom)
- [UMU](https://github.com/Open-Wine-Components/umu-launcher)
- [UMU FAQ](https://github.com/Open-Wine-Components/umu-launcher/wiki/Frequently-asked-questions-%28FAQ%29)

Нет сравнительных тестов, подтверждающих единственную лучшую сборку для Arizona.
Рабочая версия зависит от клиента игры, драйверов и оборудования. После успешной
подготовки ALOL закрепляет использованную сборку по данным префикса.
Можно выбрать другую установленную сборку или абсолютный путь к Proton.
Системный Wine использует отдельный префикс.

Для Proton/DXVK нужны подходящие 32- и 64-битные драйверы Vulkan.
При проблемах с Direct3D попробуйте WineD3D/OpenGL. При пустом окне официального
лаунчера включите отключение его GPU. Для Electron используется `--no-sandbox`,
поскольку Windows sandbox Chromium не поддерживается Wine.

## Подготовка и запуск

ALOL создаёт префикс явным вызовом `C:\windows\system32\wineboot.exe -u`.
Команда UMU `createprefix` не используется: в исследованной версии она создавала
окружение, но затем пыталась запустить пустой EXE и возвращала ошибку ShellExecuteEx.

Прямой запуск воспроизводит параметры игрового EXE из исследованного официального
лаунчера Arizona: адрес, порт, ник, память, графические настройки, параметры модов
и существующий служебный идентификатор. Идентификатор не генерируется заново
и скрывается при печати команды. Для обновления файлов используется отдельный
запуск официального лаунчера.

Публичные форматы каталога и манифестов модов также проверены по официальному
клиенту. Копий его JavaScript-кода и игровых ресурсов в исходниках ALOL нет.
Изменение API или клиента Arizona может потребовать обновления адаптера ALOL.

## Известные проблемы

### Hyprland, niri и пользовательские dotfiles

В настройках ALOL есть «Совместимый запуск Arizona: XWayland и чистое окружение».
Он включён по умолчанию и применяется только к официальному лаунчеру и установщику.
Для них убираются принудительные Linux toolkit/overlay-переменные и инъекции
`LD_PRELOAD`/`LD_LIBRARY_PATH`. При наличии `DISPLAY` выбирается X11/XWayland.
Отображение, авторизация X11 и пользовательские настройки видеодрайвера сохраняются.
Игра запускается со своими обычными переменными, включая оверлеи и Wayland-настройки.

Для новых профилей GPU официального лаунчера отключён по умолчанию. Существующий
выбор сохраняется. Если лаунчер завершается с ошибкой и GPU включён, совместимый
режим делает одну повторную попытку без GPU. Для нативного Wine Wayland или
нестандартной сборки Wine режим совместимости можно отключить.

В niri нужен работающий `xwayland-satellite`; ALOL не подменяет `DISPLAY` выдуманным
адресом и не редактирует конфигурацию WM. Отсутствующий `DISPLAY` объясняется в
журнале. См. [официальную инструкцию niri](https://github.com/niri-wm/niri/blob/main/docs/wiki/Xwayland.md).
Проверки с подставным runtime подтверждают параметры запуска и очистку окружения;
совместимость с конкретным набором dotfiles проверяется запуском Windows-лаунчера.

### Иконка и размер окна

Пакеты содержат SVG и PNG 256×256. Окно также имеет встроенную PNG-иконку,
имя приложения `alol` и совпадающую desktop-запись. При запуске отдельного бинарника
недостающие запись и иконка создаются в пользовательском XDG-каталоге;
существующие записи сохраняются. Рабочая сборка использует отдельный ID `alol-dev` и скрытые метаданные
`NoDisplay=true`: иконка видна в списке окон, пункта в меню приложений нет. SVG-loader для встроенной иконки не требуется.

Начальный размер — до 860×760 логических пикселей с учётом рабочей области монитора.
В плиточных WM окончательное размещение и размер определяются правилами композитора.

### Русский текст и служебные файлы Windows

Знаки вопроса вместо русского текста могут быть связаны с ANSI 1252 в префиксе.
ALOL задаёт `ru-RU`, ANSI 1251, OEM 866 и `LANG`/`LC_ALL=ru_RU.UTF-8` для дочерних
процессов. Если системной локали нет, ALOL создаёт её без sudo через `localedef`
в `~/.local/share/alol/locales/glibc-VERSION/` и передаёт `LOCPATH` только дочерним
процессам. При обновлении glibc используется отдельный кэш. При недоступных
`localedef` или исходниках локали установка продолжается со встроенными NLS Wine.
Это проверено на Wine 11.21: ACP 1251, OEM 866, системная и пользовательская ru-RU.
Язык рабочего стола, `/etc/locale.gen` и системный locale-archive не меняются. Описание проблемы:
[база знаний Arizona](https://chatwoot.arizona-rp.com/hc/arizona-rp/articles/1738955157-).

Ошибки `Failed to load font file ...:Zone.Identifier` возникают, когда Windows-метки
попадают на Linux в виде отдельных файлов. ALOL переносит только распознанные
метки `[ZoneTransfer]`/`ZoneId` в резервную папку, сохраняя настоящие шрифты и DLL.

### WASD и COSMIC

Опция **«Совместимость клавиатуры: WASD / COSMIC / XWayland»** включена по умолчанию,
в том числе после обновления старых настроек. При доступном `DISPLAY` игра запускается
через XWayland; без него сохраняется возможность нативного Wine Wayland.
В дочернем окружении отключаются Linux IME-перехватчики, а для игровых EXE задаётся
Wine `UseXIM=N`. Оверлеи и графические настройки игры сохраняются.
Перед изменением реестра сохраняется копия `user.reg` в `backups/input` данных ALOL.
Отключение опции удаляет добавленный ALOL override и возвращает обычный ввод Wine.

Это обход проблем маршрутизации буквенных клавиш. Он не переключает раскладку
COSMIC и не переназначает клавиши в GTA. Перед запуском выберите английскую
раскладку; для IME или нативного Wayland можно отключить опцию и сохранить настройки.
Конкретный периодический сбой WASD в игре на COSMIC ещё требует проверки игровым сеансом.

Постоянное RU в индикаторе раскладки — отдельное ограничение `GetKeyboardLayout`
в Wine. В ALOL 0.5.8 исправление включено в **ALOL-Proton 0.1.0**:
[устройство, сборка и проверка](proton.md#профиль-arizona-и-клавиатура).
Она сохраняет ru-RU и кодировки и меняет только ответы API для индикатора игры.

Источники поведения:
[Wine: запасная обработка LC_ALL](https://github.com/wine-mirror/wine/blob/master/dlls/ntdll/unix/env.c),
[Wine: настройка UseXIM](https://github.com/wine-mirror/wine/blob/master/dlls/winex11.drv/x11drv_main.c),
[glibc: LOCPATH](https://sourceware.org/glibc/manual/latest/html_node/Locale-Names.html).

## Пределы проверки

Модульные и интеграционные тесты проверяют параметры запуска, сохранение профилей,
блокировку префикса, установку и откат модов, обработку архивов, кодировки и ошибки.
В интеграционных тестах Wine/UMU и HTTP-загрузки заменены фикстурами.

Проверки GTK выполняются в доступной графической сессии, кодировки — также
на отдельном настоящем Wine-префиксе. Полный вход на сервер, античит, FPS, звук и длительная стабильность
не покрыты этими тестами. Их проверяют обычным запуском ALOL в графической сессии
на целевой машине. Совместимость со всеми серверами и сборками Wine не гарантируется.
