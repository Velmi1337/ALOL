# ALOL-Proton

[← На главную](../README.md) · [Совместимость](compatibility.md)

В ALOL 0.5.8 **ALOL-Proton 0.1.0** объединяет наш профиль запуска Arizona
и проверенное исправление индикатора раскладки EN/RU. Основа — закреплённый
**GE-Proton11-11**. Пересобраны только `user32.dll` для 32 и 64 бит; DXVK,
обработка игровых клавиш, текстуры и графические параметры сохранены.
Ранние exp3 и Keyboard/kbd1 остаются отдельными версиями для возврата.
Подтверждённого преимущества по FPS над обычным GE-Proton или Windows не заявляем.

## Подготовка

Нужны Linux x86_64, UMU и необходимые графические драйверы. В ALOL откройте
**Настройки → Дополнительно → Окружение и пути к файлам → Создать и выбрать ALOL-Proton**.
При первой подготовке загружается около 539 МиБ базы GE и 71 МиБ исправления
с полными изменёнными исходниками Wine. Уже скачанная проверенная база используется
повторно. Нужно не менее 4 ГБ свободного места. Компиляторы пользователю не нужны.

```sh
alol runtime-prepare
alol runtime-prepare --select
```

Первая команда только готовит сборку, вторая также выбирает её для следующего
запуска. В списке Proton можно выбрать **ALOL-Proton**; успешная подготовка через
кнопку закрепляет абсолютный путь к конкретной версии. Если настройки изменились
параллельно, сборщик сохраняет новый выбор пользователя.

Runtime находится в `$XDG_DATA_HOME/alol/runtimes/`, обычно
`~/.local/share/alol/runtimes/`. Для `run-dev.sh` используется
`.dev-data/data/alol/runtimes/`. Рабочая копия и установленный ALOL используют
разные данные. Старые runtime, игра и моды при подготовке не заменяются.
Для возврата выберите прежний путь в поле Proton и сохраните настройки.

## Профиль Arizona и клавиатура

Слой запуска применяет только выбранные пользователем режимы совместимости:

- совместимый ввод обходит IME-перехватчики и использует существующий XWayland;
- официальный Windows-лаунчер получает очищенное от конфликтующих dotfiles
  окружение и необходимые параметры Electron без повторов;
- служебные команды и запуски без назначения Arizona передаются без игровых
  исправлений; настройки FPS, VSync, GPU, синхронизации и DXVK не подменяются.

Обычный Wine может возвращать в `GetKeyboardLayout` язык локали вместо текущей
раскладки XKB. Патч отделяет запросы `GetKeyboardLayout` и
`GetKeyboardLayoutNameA/W` от локали и преобразования клавиш. Небольшой помощник
наблюдает события смены группы и замены карты XKB и публикует Windows ID языка
в четырёхбайтовом отображении памяти. Запросы игры читают память: опроса X-сервера
на каждом кадре и записи вводимого текста нет. WASD, `ToUnicode`, ru-RU,
Windows-1251 и OEM 866 сохраняются.

Для индикатора нужны включённая **совместимость клавиатуры** и X11/XWayland.
Нативный Wine Wayland без этого режима пока использует обычный ответ Wine.
Помощник передаёт базовый ID языка, не переназначая варианты клавиатуры.
Неизвестная карта или остановка помощника возвращают обычное поведение Wine.
Помощник запускается только для игры и завершается вместе с её сеансом.

ALOL передаёт Proton `HOST_LC_ALL=ru_RU.UTF-8`: иначе Proton удаляет обычный
`LC_ALL`, и унаследованный `LC_CTYPE=C.UTF-8` может вернуть английскую кодовую
страницу. Системная локаль и язык рабочего стола не меняются.

## Проверка и лицензии

`runtime/base.json` содержит закреплённые URL, размеры и SHA256 базы GE,
готового исправления, обеих DLL и полных изменённых исходников Wine.
`runtime/build.py` проверяет архивы, запрещает внешние ссылки и выходы путей,
блокирует параллельную подготовку и публикует результат атомарным переименованием.
Повреждённая существующая версия сохраняется с сообщением об ошибке.

Оригинальный вход Proton сохранён как `proton.alol-upstream`, исходный `version`
оставлен для корректных миграций префикса. Прежние DLL доступны рядом как
`user32.alol-upstream.dll`; `alol-runtime.json` содержит рецепт и контрольные суммы.
При запуске ALOL также проверяет целостность исправления.

Все исходные лицензии GE и компонентов сохраняются. Apache-2.0 и NOTICE ALOL
относятся к нашему слою; патч Wine остаётся **LGPL-2.1-or-later**.
В каждой готовой сборке находится **ALOL-WINE-SOURCE.tar.gz**: полные изменённые
исходники Wine, LGPL, точный патч и инструкция пересборки. Эти исходники также
доступны внутри опубликованного архива исправления. Личные настройки,
Wine-префиксы и игра в архивы релиза не входят.

Подготовка из уже скачанной базы:

```sh
python3 runtime/build.py --output-root ./runtime-output --cache ./runtime-cache \
  --archive /путь/GE-Proton11-11-x86_64.tar.gz
python3 tests/proton_runtime.py
```

Для разработчиков сохранён `runtime/build_keyboard.py`: он собирает отдельную
локальную kbd1 из точных исходников Wine и полной серии патчей GE.
Нужны gcc, clang, lld, llvm, make, flex, bison, autoconf, perl, patch и curl.
Сборщик сам не устанавливает системные пакеты; для обычной подготовки он не нужен.

## Проверки

```sh
python3 tests/keyboard_layout.py \
  --runtime .dev-data/data/alol/runtimes/ALOL-Proton-0.1.0-x86_64
```

Тест использует частный Xvfb и временный префикс: настоящие 32/64-битные Windows
EXE проверяют EN → RU → EN, замену всей карты, физические WASD, кириллицу,
ACP/OEM, ru-RU и возврат к обычному Wine без помощника. `--umu` повторяет проверки
через настоящий UMU с кэшем Steam Runtime рабочей копии. Для воспроизведения
прежней ошибки можно указать exp3 и `--baseline`. Системная раскладка не меняется.
Исправление также подтверждено игровым сеансом пользователя.

Для сравнения производительности используйте одинаковую сцену, разрешение,
графические настройки и число игроков, прогретый кэш и чередование версий A/B/A.
Небольшая разница между разными серверами не подтверждает прирост FPS.

Исходное поведение API:
[Wine: GetKeyboardLayout](https://github.com/ValveSoftware/wine/blob/c53678ab22a85f0fad3588dd34f0452a463bd015/dlls/win32u/input.c).
